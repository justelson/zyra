# Desktop developer workflow

Quick Open uses **Ctrl+P** (Cmd+P on macOS). Search filenames, append `:42` to jump to a line, or use **Ctrl+Shift+F** to search file contents. The search is scoped to the current chat's working folder; the folder button can select another folder. Content search accepts a `*` file filter such as `*.ts`, respects Git ignores, skips binary and oversized files, and bounds its results and disk reads. Before reading, it verifies the opened native descriptor against the checked regular file and rechecks path containment; supported platforms also open without following a leaf symlink. Concurrent file or parent-junction replacement is skipped without reading the replacement. Older results stay visible while a newer query is pending, but cannot be selected until that query resolves. Late responses cannot replace a newer query or another folder's results.

Select text in a code/text editor and choose **Ask Zyra**. In diff review, drag line numbers and choose **Ask Zyra**. The attachment contains the exact text, file, line range, workspace and revision; diff selections also identify the before/after side. Partial patches cannot invent omitted lines between hunks. The attachment is a preserved snapshot, not a live view of later edits. File selections compare the disk content at attachment time when a complete read is available, and mark a changed source. The original target chat is retained if navigation changes while that check is pending.

The branch control in the conversation header opens a compact anchored menu with the project, **Open in**, **Project scripts**, **Changes**, and the current branch. Scripts and changes open on demand, with Back returning to the small menu. The branch selector loads local refs when expanded, supports search, and reports checkout failures without silently stashing local edits.

The workspace menu and its deeper pages share a 320 by 280 pixel size, clamped to the available window space, with scrolling inside. App and branch choosers float in separate solid-background popups without resizing that menu. Their native input regions follow the rendered boxes rather than covering the whole window; other window controls remain clickable. Outside clicks dismiss them without consuming the clicked action, and Escape closes a chooser before the workspace menu. The terminal label and launch use the saved default shell. Script launch controls share a rounded triangle icon.

- **New chats:** use the ordinary chat controls. A new Git-project composer has a tucked branch/worktree preference: its first prompt includes temporary system context asking the agent to create an isolated worktree. The visible user prompt stays intact; this preference does not claim a worktree has already been created. Existing chats keep their saved scopes. Worktrees are retained; no automatic merge or removal occurs.
- **Project scripts:** execute an existing package script using the declared package manager, then lockfile detection, then npm. Tests, builds, checks, development and other scripts have distinct sections and colors, with tests first. Compact wrapping chips have a left play control; starting, running and stopping update only that script's control. Running scripts can be stopped independently. Select a task label to inspect its real output and run history, including previous runs of removed scripts. Local server URLs use the app's normal link-opening policy. Output can be attached to a chat. Running a dev server does not count as a completed check. Output, task history and concurrency are bounded.
- **Changes:** filter repository files by name and staging state, inspect diffs, stage/unstage individual files, review a commit, or review a commit/push/PR through the existing Git workflow. Pending indicators belong to the affected file or action. Git writes are serialized; independent diff reads and script controls remain usable. Review refreshes the staged-file list and captures the staged patch. Confirmation lists those files and patch. Changes to the staged patch require a new review. The panel commits the repository index, including any files previously staged elsewhere; the preview makes that scope visible. This feature does not add hunk staging.

Check evidence comes from owned package tasks and actual exit codes, not assistant prose. Each task captures the source revision; subsequent source edits make its evidence stale. The revision includes HEAD, tracked working-tree changes and bounded untracked-file contents. If a revision cannot be verified, evidence is treated as stale. Missing checks remain **Not run**. Records persist in the private application profile. Tasks recorded as running become stopped after application restart; the app does not silently rerun them. These desktop tasks are separate from canonical agent-server background processes.

**Undo edit** appears for a complete, authoritative recorded text change in turn review. It previews one file's inverse patch and requires confirmation. Git checks the inverse patch against the current working tree; a changed file after preview invalidates the token. It preserves pre-existing unrelated edits, staging and commits, and refuses conflicts, symlinks, out-of-root paths, binary changes, renames and unsupported mode changes. Undo is unavailable for a provisional/truncated patch and while that reviewed turn is running. This is per-edit restoration, not whole-turn filesystem checkpointing or command rollback.

File content is published independently of renderer warming. The editor can initialize after readable text appears. Cached files still validate against disk; failed reads remain errors. This removes a renderer-import dependency from file opening; it does not establish a measured end-to-end speed advantage or a long-running memory/latency improvement.

The `@` file/folder picker, `/include` picker and command/skill menu share a tucked drawer with compact file-type icons, filenames beside directory paths, and source badges using provider logos and distinct colors. Commands and skills share one alphabetical list. New-chat drawers open below the input; bottom-chat drawers open above it. Both fade and slide from behind the composer, close with Escape, a close button or outside interaction, and leave other actions usable. File, folder, command and skill references render as atomic removable inline chips while retaining the complete prompt tokens, selection offsets, copy/cut text and native undo.

New-chat attachments reserve space between the greeting and input. Images use small thumbnail/filename pills and removal on hover or keyboard focus (always available on touch). Clicking outside the remove control opens the existing image viewer; clipboard references can use the captured image without resolving a pseudo path, while real files retain their full-resolution source. Code/text snapshots use a compact card with a snippet and line details. **Ask Zyra** appears above an editor selection rather than adding a toolbar row. The bottom composer retains its compact floating attachments and existing file-opening action.

Chat settlement is a canonical agent-server catalog property. Desktop and browser actions use the existing bridge; mobile uses `catalog.update`. Catalog metadata events refresh the surfaces, busy/attention states stay active, and new agent work clears settlement before publishing. Saved local choices are migrated only if the server has no explicit choice. Desktop serializes this migration in one shared job, clears only acknowledged choices, and backs off failed retries for 60 seconds. Each settlement acknowledgment updates the session directly without awaiting a full catalog import. Desktop caches the canonical flags in its existing metadata table for cold reopening; that cache does not decide settlement. Older servers without the property retain the legacy display fallback, while attempted mutations report unsupported/disconnected errors. Ctrl+K usage shows per-account window pies and an average row; Providers and Limits offer **Make primary**, using the account-pool update API.

Account identities in Ctrl+K, Limits and provider connections show saved random aliases by default. Click a name to reveal or hide its email; reveal expires after 20 seconds and clears when the window loses focus. Hidden emails are absent from rendered text, tooltips and accessibility labels. The pencil edits the alias, and acknowledged changes update the open usage surfaces together. Names are private display metadata keyed by stable account ID, stored separately from credentials; renaming does not refresh authentication. Older account snapshots fall back to an opaque account label rather than an email. Command-palette icons and titles share hover, selection and focus colours and transition timing.

## Verification

From the repository root:

```powershell
npm --prefix desktop run test:developer-workflow
npm --prefix desktop run test:keybindings
bun --cwd desktop scripts/test-file-preview-opening.tsx
```

Backend tests use temporary Git repositories and real owned script processes. Renderer tests run hidden isolated Electron windows with IPC, the store boundary, preview chrome and diff worker transport stubbed. They exercise the actual search hooks, dialog, selection action, context bus and prompt serialization, plus pending Changes rendering. They do not prove installed-app appearance, real Monaco/Pierre pointer interactions, provider traffic, OS notifications or multi-hour soak behavior.

The composer presentation test renders the real composer, attachment shelf, image viewer and picker with compiled Tailwind styles. It checks measured spacing, small image pills, keyboard removal visibility, click-to-open/removal, three-line writing height, drawer placement and mid-animation opacity/translation in both directions, dismissal, inline chip deletion/undo and raw-token copying. Controller/settings inputs, prompt-resource IPC, analytics and the unused syntax renderer are fixture boundaries. Set `ZYRA_COMPOSER_SCREENSHOTS` to a local directory to capture attachment, picker and drawer states. Workspace rendering also verifies the 280px menu, progressive script details, branch lookup/checkout errors and dismissal.

`node scripts/test-chat-settlement.mjs` exercises a real isolated agent server and three protocol clients, including server restart, cross-client changes, busy guards, new work and migration ordering. Desktop settlement/navigation and SQLite history-cache checks are available through their owning targets. `node scripts/test-zyra-prompt-errors.mjs` checks hidden worktree context and cleanup, using a synthetic provider. Android's `CanonicalChatSettlementTest` checks canonical parsing, conflicting saved choices, busy guards and migration markers. These checks do not prove a physical phone, installed preview server activation or actual agent-created worktrees.
