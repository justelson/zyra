# Chat rendering preview

## Question composer

From `desktop`, start the isolated composer preview:

```powershell
node node_modules/vite/bin/vite.js --config scripts/composer-preview.config.ts
```

Open `http://127.0.0.1:5187/composer-review.html`. It mounts the production message and question composers with synthetic questions, preserving their shared shell, attachment row, model controls and send actions. Use the type selector to switch between the normal composer and questions. Reset and light/dark affect only this preview. No answers or preferences reach the installed app or a provider.

Questions use the same attached menu surface and 220ms drawer motion as commands and skills. Section bodies and the composer measure their intrinsic content height and animate size changes over 220ms, rather than snapping when fields or the textarea change. A single 160ms opacity/4px translation replaces per-row blur, scale and stagger. Input state updates immediately; ResizeObserver keeps dynamic wrapping and attachment sizes accurate, and reduced motion disables both effects. The ordinary input frame stays below that surface, with labeled Continue/Back/Submit actions. An incomplete review uses an enabled Finish questions action that opens the first unfinished answer without submitting. In this mode, Continue walks directly through the remaining unfinished questions, skipping completed answers, and returns to review only after every gap is finished. The mode and position survive panel remounts. Review exits the flow explicitly; ordinary review edits still return directly to review. Submit appears only when every answer is complete or explicitly skipped. Unanswered fields are not mislabeled as skipped. For multi-question requests, the existing counter opens the shared anchored question picker. Completed answers have a check and short preview; the current question is highlighted. Switching preserves drafts, expands a minimized tray, and retains return-to-review behavior. Escape/outside click dismiss the picker, keyboard arrows/Home/End navigate it, and active recording or submission disables switching. Question dictation uses the existing recorder and transcription hook; Stop fills the editable answer, while voice Send advances using the completed transcript. Changing requests cancels pending transcription. Bounded numeric questions use a compact, full-height filled-bar scrubber with a vertical handle, inline label, directly editable value, and supplied min/max/step. Numeric and date questions hide the duplicate message textarea while retaining navigation and dictation. The scrubber and value share the canonical answer, including dictation. An untouched or cleared slider remains unanswered; selecting the lower endpoint explicitly records it, including zero. Unbounded numbers retain the plain field. Priority rankings drag from the entire row; the six-dot grip is decorative, without a separate button background. Up/down buttons remain available for keyboard users and do not activate row dragging. A portaled drag overlay settles into the final slot over 180ms while hiding the source through the handoff. Rank badges preview the projected order during dragging with a 140ms number transition; only a successful drop commits the order, and cancellation preserves it. Reduced motion disables settling and number effects. The renderer test samples off-center drops for overshoot, verifies animated live ranks, and cancels a multi-row move.

Date questions use a compact custom anchored calendar, not the browser's native date control or the import-history modal. It supports month navigation, roving day focus with arrows/Home/End/Page Up/Down, year jumps with Shift+Page Up/Down, Today/Clear, Escape/focus restoration and outside dismissal. Dates remain local `YYYY-MM-DD` values; impossible dates from dictation are rejected. `bun scripts/test-assistant-question-date.ts` checks leap years, ISO round-trips, month/year boundaries and validation without loading the app. The question renderer tests cover selection, clearing, required answers, dictation and narrow calendar placement.

Dictation follows the existing transcription preference and is disabled for ranking/review and unavailable states. The preview's voice action inserts explicitly labeled sample text without a provider request.

With the server running, `node scripts/test-composer-preview.mjs` checks all eight field types, number bounds, optional skips, review/edit, retained answers, custom choices, submission, attached-surface geometry, default-frame/input parity, intermediate entrance/expand/collapse heights, section-to-section height changes, and composer resizing when numeric questions remove the textarea. It captures dark, light and 390px-wide screenshots under ignored `docs.local/reviews/question-composer/`. The renderer check stays hidden and closes after verification. `node scripts/test-assistant-sidebar-continuity.mjs --user-input-form` covers attachments, clipboard, offline drafts, question dictation, cancellation, late-result isolation, numeric answers and async focus isolation.

Responses are synthetic; nothing is installed, executed, granted or redeemed. Normal, slow/busy and failed response modes are available.

With the server running, `node scripts/test-permissions-preview.mjs` captures every catalog case and representative narrow layouts, exercises safe synthetic response paths, and writes pointer/layout findings to ignored `docs.local/reviews/permission-requests/audit.json`. It does not replace live approval panels. Broader tool permissions use an unchecked `ComposerCheckbox` in the footer's left side, not a split-button dropdown or an extra body row. The short label preserves the exact scope/duration, while its accessible name and hover hint identify the permission in full. Selection updates the primary label without approving; exact app operations offer no broader scope. Terminal prompt-muting also lives in the footer. All proposal checkboxes use the same theme-aware app control with a native keyboard-accessible input and visible focus ring. Routine help uses the header info tooltip. Caution notes use an amber warning-icon tooltip on hover, keyboard focus or click, consistently across action confirmations, executable trust, reset credits, updates and browser safety overrides. Transaction details such as prices, renewal terms, recipients and scope remain visible; blocking states and errors remain inline. `node scripts/test-permission-composer-review.mjs --warnings-only` checks the warning families and dismissal without authorizing anything. Device Project checkboxes share one wrapping row instead of a vertical list, with attached-folder help in the header tooltip. External/native boundary examples now use the same attached composer, one compact handler/destination row and a header explanation. Their Next request button only navigates the catalog; it does not impersonate a native authorization. `node scripts/test-permission-composer-review.mjs --compact-only` checks all nine boundaries and Project-selection density on desktop and narrow screens. Enter in the optional preserved draft never approves. Requested capabilities share a compact inline strip with one icon per group and no visible group-heading rows. Short labels retain full accessible names. Incognito and read-only context stay visible in the requester line instead of separate body rows. The footer has no placeholder model label. Empty groups are omitted, and the strip wraps on narrow screens without hiding capabilities. `node scripts/test-permission-composer-review.mjs --capabilities-only` checks all twelve individual rights, mixed requests and light/dark/narrow presentation. File separators appear only between rows. Long commands and explanations start as compact disclosures without discarding their content. Edited file rows show addition/deletion counts; hover, keyboard focus or touch opens a viewport-clamped, content-sized preview using the existing syntax-highlighted inline diff renderer. Those example patches are synthetic. `node scripts/test-permission-composer-review.mjs --hover-only` checks file previews and captures desktop/narrow evidence without traversing the whole catalog. Normal/slow/error modes exercise busy, retry and request-switch isolation. `node scripts/test-permission-composer-review.mjs` checks every catalog case, explicit decisions, form validation and narrow/light layouts, with private evidence under `docs.local/reviews/permission-composer/`.

## Custom audio embeds

Run `npm --prefix desktop run preview:audio`, then open `http://127.0.0.1:5201/audio-review.html`. The preview uses the actual Markdown renderer and shared audio player with synthetic local MP3/WAV files, no app bridge or provider. Its header switches between the intentional two-player test, the real Message layout and a one-second Short clip. `?grouped=1` opens Message directly; `?view=short` opens the short sample. No private audio is required.

Inline audio and file-preview audio share one custom play/pause, seek, time, speed and mute control set. The native audio element is hidden and never autoplays. Starting another custom player pauses the old one without stopping unrelated voice audio. File-preview arrow navigation ignores focused audio controls.

Real rendered Markdown groups linked audio outputs into one player with a file selector. Exact repeated resolved sources become one option, while different formats and recordings remain available. Grouping is local to the compiled Markdown region, does not mutate a caller-owned prepared tree, and never suppresses a later message. Explicit review pages may use `audioPresentation="individual"`; render-cache identity and memoization include this choice.

During playback, an owner-document animation frame reads the real media clock and paints the range/progress directly. It does not extrapolate through buffering or seek ahead, does not snap fractional values to a 0.1-second step, and stops on pause, end or unmount. React updates the visible clock only when its whole-second value changes. Seeking still updates immediately.

Run `npm --prefix desktop run test:audio-player` for leaf/SSR policies and actual hidden Electron pointer/keyboard interactions. The renderer starts its own isolated loopback server, uses temporary profiles and silences its own audio output. It checks MP3/WAV playback, source selection and focus, one-at-a-time playback, one-second progress with coarse `timeupdate` delivery blocked, no autoplay, and desktop/narrow/light layout. `ZYRA_QA_SCREENSHOT_DIR` saves private screenshots. No FFmpeg installation is needed by this target; the synthetic MP3 bytes and PCM generator live beside it. Installed native-overlay and physical speaker acceptance remain separate.

## File reads and pasted video

The production read row chooses its preview by file/result type. Text, code, Markdown, JSON and CSV reads retain their exact captured source, whitespace and line range in the read-only source viewer. Image reads use an image icon and the shared zoom/fit viewer, preferring recorded image bytes or a canonical cached image over the original file. Legacy path-only images preview the file without calling it captured source. Video/audio use media controls without autoplay; PDF/Office reads use their existing document viewers. Unsupported binary files and missing/undecodable media have explicit unavailable states rather than a source editor. Relative media paths use the known project root when available. Captured data URLs are not retained as image-dimension cache keys.

Read previews share one selection per Chat. Repeated same-path calls retain separate activity IDs and captured images. Lazy reads are single-flight, errors remain retryable, Escape cancels pending preview intent, and an older response cannot cover a later selection or reopen after Chat navigation. Consecutive action grouping still respects visible narration/user/terminal boundaries; transient local/provider turn aliases do not create extra batches.

Composer and question-answer video paste uses the real clipboard File payload, preserves binary bytes, and stores a durable file reference. Video pills, previews, draft/queue recovery and sent-history reopening retain their video type. The shared paste collector uses FileList when present and file items as fallback, without swallowing ordinary text for null file items. Files with text MIME, including TypeScript source, are not classified as video just because an extension is ambiguous. Storage failures never create a pretend video attachment, pending file work cannot be silently omitted by Send, and late reads cannot attach to another Chat/request. Video is provided to analysis tools as a file, not mislabeled as native image or native model video input.

Desktop attachment persistence has a 64 MiB decoded limit checked before file allocation. The browser bridge's existing 32 MiB encoded request limit still applies. Larger requests fail visibly rather than truncating the file. Media decoding depends on the browser's supported codecs.

Run from `desktop`, without starting a preview server:

```text
npm run test:assistant-read-media
npm run test:assistant-video-paste
node scripts/test-assistant-sidebar-continuity.mjs --tool-media
node scripts/test-assistant-sidebar-continuity.mjs --video-paste
```

Set `ZYRA_QA_WIDTH=390` for narrow geometry and `ZYRA_QA_SCREENSHOT` for a private screenshot destination. These hidden disposable Electron fixtures use synthetic File events, real local image/H.264 decoding, actual paste/presentation handlers and isolated storage adapters. They never modify the OS clipboard or contact providers. The unused Monaco editor runtime is isolated from these media fixtures; exact source/model-path semantics have their own rendering assertions. Offscreen CSS animation clocks can remain at zero, so media geometry captures finish finite entrance animations explicitly. Installed native-overlay, physical Windows clipboard and provider acceptance remain separate checks.

## Chat rendering

Run from `desktop`:

```powershell
node node_modules/vite/bin/vite.js --config scripts/providers-review.config.ts --port 5184 --strictPort
```

Open `http://127.0.0.1:5184/rendering-review.html`. It uses production chart, Mermaid, plugin activity and virtual chat timeline components with fictional local data. It never signs in, sends requests to providers or touches installed-app threads. Chat labels and settlement changes are intentionally absent from this preview.

The Streaming section has **Replay diagram**, **Replay visualization** and **Replay response**. Mermaid stays on a dotted **Creating diagram** canvas while its fence is incomplete; visualization HTML uses a distinct **Creating visualization** chart panel until its tag closes. Finished content shows **Loading diagram** or **Loading visualization** while the renderer prepares it. Creating and loading labels shimmer with fixed-width dots cycling 3, 2, 1, 2, 3; app and OS reduced-motion settings disable the motion. The response replay sends paragraph deltas through the production streaming Markdown renderer and virtual timeline. Scroll upward while it runs to release bottom-follow. The inline and expanded Mermaid canvases use the same dotted grid; the expanded viewer supports drag, zoom, fit and keyboard navigation.

With the preview server running:

```powershell
node scripts/test-rendering-review.mjs ../docs.local/reviews/plugins-ui-review
bun scripts/test-streaming-mermaid.ts
node scripts/test-visualization-renderer.mjs
node scripts/test-visualization-renderer.mjs --extension
```

The first check launches an isolated Electron renderer and exercises chart compactness, both diagram grids, expanded sizing/zoom/fit/physical drag/focus restoration, plugin icons and structured results, partial-fence streaming, animated bottom-follow, manual release and completion. Screenshots go to the supplied directory. The visualization fixtures separately use the real renderer and MV3 sandbox CSPs and verify sanitization, scriptless exports, fonts, stable gutters, animated disclosures and point tooltips. The scroll benchmark verifies retained iframe state and bounded sanitizer caching.

These checks use simulated events and local test data. They do not prove that the installed desktop app or a running agent server has loaded the changes. On the next update, restart the agent server before testing the pending server-side changes and optimizations.
